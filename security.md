## 🔄 Sharing And Receiving Configurations

Configs move between people, and that creates a specific set of problems.

**What travels safely**

| **Item** | **Safe** |
| --- | --- |
| Preset values | yes |
| Keybinds | yes, but check for collisions |
| Overlay colours | yes |
| Module files | no — version mismatch |
| Identity settings | no — machine specific |

**The version mismatch trap**

A preset from a different build may load partially or not at all. The symptom is
a menu that opens with empty values. That is a schema difference, not corruption.

**Receiving a config: the order**

1. Load it into a **copy** of the folder.
2. Check that every value is present.
3. Compare keybinds against your own.
4. Test with everything disabled first.

**Why a copy**

A bad config in a copy costs nothing. A bad config in your working folder costs
the tuning you had before you tried it.

**Sharing your own**

Share the preset file, not the whole folder. The folder contains module binaries
that are build-specific and useless — or actively wrong — on someone else's
version.
